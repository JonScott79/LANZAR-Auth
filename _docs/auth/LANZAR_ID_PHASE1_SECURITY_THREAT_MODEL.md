# LANZAR ID — Phase 1 Security Threat Model
**Document ID:** `LID-REV-PHASE1-THREATS`  
**Scope:** LANZAR ID Milestones 1.1–1.5  
**Date:** 2026-11-15  

---

| # | Threat | Attack Scenario | Existing Mitigation | Remaining Weakness | Severity | Recommended Remediation |
| :-: | :--- | :--- | :--- | :--- | :-: | :--- |
| 1 | **Unauthorized Client Registration** | Unauthenticated user or non-admin calls `POST /api/admin/id/clients` to register a rogue OAuth client. | `authenticateAdminMiddleware` verifies Firebase ID token (`checkRevoked: true`), active LANZAR session, and `admins` Firestore record; fails closed `503` if middleware missing. | None in route; relies on `admins` collection integrity. | **Low** | Restrict `admins` writes in Firestore Security Rules to Admin SDK / ops tooling only. |
| 2 | **Cross-Tenant Data Access** | Tenant A admin supplies `tenantId: "tenant_b"` in body/query/header to read, update, disable, or audit Tenant B clients; or client replays token/session across tenants. | `resolveAdminTenantScope()` derives tenant from server-verified `req.adminContext`; `oauthRoutes`, `oidcRoutes`, `store.authorizeRefreshGrant()` bind and verify `tenantId` at every hop. | Legacy `adminRoutes.js` endpoints do not yet use `req.adminContext` tenant scoping. | **Medium** | Migrate or scope `adminRoutes.js` behind `platform_admin` role check before onboarding external tenant admins. |
| 3 | **Authorization-Code Interception & Replay** | Attacker intercepts `code` from redirect and attempts redemption or races legitimate client. | Single-use SHA-256 `codeHash`, atomic `initiateRedemption` lock + fence tokens, `REPLAY_DETECTED` compromises ceremony and revokes session/family. | None significant when HTTPS redirect URIs are enforced. | **Low** | Enforce HTTPS-only redirect URIs in production (`filterProductionRedirectUris` already strips loopback). |
| 4 | **PKCE Bypass** | Client omits `code_challenge` or downgrades `code_challenge_method` to `plain`. | `POST /oauth/authorize` strictly requires `code_challenge_method === 'S256'`; `store.js` validates S256 `code_verifier` on redemption. | None. | **Low** | Maintain S256-only enforcement; add periodic automated regression checks. |
| 5 | **Refresh-Token Theft & Replay** | Stolen refresh token is replayed after legitimate client rotates it (or with wrong `client_secret`). | Rotating `sequenceNumber` + `currentActiveTokenHash` in `/tenants/{t}/token_families/{f}`; replay immediately revokes family & session; confidential `client_secret` checked before rotation. | No IP/device binding enforcement on refresh beyond audit metadata. | **Medium** | Monitor `compromised_ceremonies` / `security_outbox` alerts in production; consider anomaly alerting. |
| 6 | **Client-Secret Compromise / Weak Secret** | Attacker compromises confidential client secret or offline-cracks weak caller-chosen 16-char secret from DB leak. | Secrets stored as SHA-256 hex, compared with `timingSafeEqual`, stripped from all responses/logs; `401 invalid_client` on mismatch. | Caller-supplied 16-char secrets use unsalted SHA-256; no CSPRNG generator or dual-secret rotation endpoint. | **Medium** | Implement server-generated 256-bit CSPRNG secrets with one-time disclosure and `previousClientSecretHash` grace-window rotation. |
| 7 | **Signing-Key Compromise** | Attacker obtains encrypted private key from `system_signing_keys` or compromises `SIGNING_KEK_V*`. | Private keys encrypted with AES-256-GCM (`12B` IV, `16B` tag, AAD bound); KEK validated in staging/prod; `revokeSigningKey()` removes key from JWKS immediately. | External RPs caching `/.well-known/jwks.json` (`max-age=60`) may accept revoked-key JWTs for up to 60s. | **Medium** | Store KEKs in Cloud KMS / Secret Manager; use short 15m access-token TTLs and online `/oauth/userinfo` for sensitive actions. |
| 8 | **Session Hijacking** | Stolen `access_token` or session cookie used after user logs out or client is disabled. | `/oauth/userinfo` performs online check of session `status === 'active'`, `revoked !== true`, `tenantId`, and live `client.enabled`. | Resource servers verifying JWTs offline (without UserInfo/introspection) accept tokens until `exp` (900s). | **Medium** | Keep `ACCESS_TOKEN_TTL_SECONDS = 900` (15m) and require online `/oauth/userinfo` or session check for high-value operations. |
| 9 | **Privilege Escalation** | Tenant admin injects `x-admin-role: platform_admin` header or `platformAdmin: true` in request body. | `authenticateAdminMiddleware` populates `req.adminRole` / `req.adminContext` strictly from verified ID token + `admins` doc; malformed tenant claims fail closed `403`. | None in M1.4/M1.5 routes. | **Low** | Keep `admins` collection protected; audit all `platform_admin` grants. |
| 10 | **Audit-Log Manipulation** | Malicious tenant admin or compromised client attempts to overwrite or delete `/tenants/{t}/admin_audit_logs/{id}`. | `AuditLogService` uses unique `aud_<ts>_<hex>` IDs with `tx.create()` in the same transaction as mutations; no update/delete endpoints or methods exist. | Application-level append-only is NOT database-enforced immutability; compromised Admin SDK or missing Firestore Rules could mutate docs. | **Medium** | Deploy Firestore Security Rules denying all client `read`/`write`/`update`/`delete` on `admin_audit_logs`, and stream audit events to Cloud Logging / immutable sink. |
| 11 | **Firestore Data Exposure** | Direct client SDK queries against `system_signing_keys`, `oauth_authorization_codes`, `token_families`, or `admin_audit_logs`. | Backend uses Admin SDK; API responses strip `clientSecretHash` and private keys. | Firestore Security Rules are not yet verified/deployed in this repo for M1.1–M1.5 collections. | **High** | Author and deploy deny-by-default Firestore Security Rules for all backend-only collections before production launch. |
| 12 | **Denial of Service (DoS)** | Flood of `/authorize`, `/token`, or JWKS/UserInfo requests, or Firestore transaction contention. | `rateLimiter.js` limits `/authorize` and `/token`; `SigningKeystore` caches JWKS for 5s; `/.well-known/jwks.json` has `max-age=60`. | `rateLimiter.js` is in-memory per process; `POST /oauth/token` refresh and `/api/admin/id` lack distributed rate limiting. | **Medium** | Add edge/WAF rate limiting (Cloudflare / Cloud Armor) and Redis-backed rate limiting for multi-instance deployments. |
| 13 | **Misconfigured Production Environment** | Production/staging boots with dev KEK, dev `TOKEN_RECEIPT_KEY`, or localhost redirect URIs enabled. | `isProductionOrStaging()` checks `NODE_ENV` and `APP_ENV` for `production`/`staging` and rejects dev keys; `filterProductionRedirectUris()` strips all loopback/localhost variants. | `checkIsProduction()` in `clients.js` checks `production` (not `staging`), which is intentional for staging localhost testing unless staging should also strip localhost. | **Low** | Validate all env vars at startup in CI/CD deployment checks and health probes. |
| 14 | **Administrative Account Compromise** | Compromised `admins/{uid}` account disables clients or registers malicious redirect URIs. | Admin login requires MFA (`isAdmin` triggers MFA in `/authorize`); every admin mutation records an atomic audit log with `actorUid` and `correlationId`. | Disabling a client does not automatically revoke existing sessions if an admin re-enables it; compromised `platform_admin` has cross-tenant reach. | **High** | Enforce hardware/TOTP MFA for all admins, alert on `platform_admin` actions, and add compromised-client cascading session revocation. |
